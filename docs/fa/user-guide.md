# راهنمای کاربری

[English](../en/user-guide.md) · [Deutsch](../de/user-guide.md) · [معرفی پروژه](../../README.fa.md).

## اجرا و ورود

برای ساخت پروژه به JDK نسخهٔ ۲۱ یا بالاتر نیاز دارید. در ریشهٔ پروژه، در لینوکس و مک دستور `bash scripts/run-demo.sh` و در PowerShell دستور `./scripts/run-demo.ps1` را اجرا کنید. آدرس `http://127.0.0.1:8080` را باز کنید. مقدار `BOOTSTRAP_TOKEN` که در اولین اجرا چاپ می‌شود را در فرم ورود قرار دهید. متن اصلی توکن فقط همان بار نمایش داده می‌شود و تنها هش آن ذخیره می‌شود. توکن را در Git یا گزارش عمومی خطا قرار ندهید.

انتخاب زبان قبل و بعد از ورود در دسترس است. زبان فارسی چیدمان را راست‌به‌چپ می‌کند؛ کدها و شناسه‌های فنی چپ‌به‌راست باقی می‌مانند. توکن ورود فقط در حافظهٔ مرورگر نگهداری می‌شود و در Local Storage قرار نمی‌گیرد. با بارگذاری مجدد صفحه باید دوباره وارد شوید.

دمو دارای پنج اتصال و یازده پروایدر منتشرشده است. سرویس‌های مقصد به‌صورت محلی شبیه‌سازی شده‌اند و اطلاعات نمونه ساختگی است. با Ctrl+C برنامه را متوقف کنید. کاتالوگ رمز‌شده در `var/` باقی می‌ماند و راه‌اندازی مجدد، تنظیمات و نتایج قطعی ثبت‌شده را حفظ می‌کند.

## اتصال، پروایدر و سرویس منتشرشده

اتصال شامل نوع کانکتور، تنظیمات مقصد و اطلاعات محرمانه است. پروایدر شامل عملیات، پارامترهای نوع‌دار، درخواست یا SQL، انتخاب خروجی و سیاست اجراست. انتشار، تصویری ثابت از نسخهٔ پروایدر و یک URL قابل فراخوانی می‌سازد. تغییر پیش‌نویس، نسخه‌های منتشرشدهٔ قبلی را تغییر نمی‌دهد. اطلاعات ورود اتصال در زمان اجرا خوانده می‌شود؛ بنابراین می‌توان آن را مستقل تغییر داد و انتشار به معنای ثابت‌شدن کل محیط نیست.

مدیر اتصال و کلیدها را مدیریت می‌کند. طراح پروایدر می‌سازد و منتشر می‌کند. فراخواننده فقط به پروایدرهای صریحاً مجاز دسترسی دارد. ممیز اطلاعات عملیاتی مجاز را می‌بیند. مدیر اولیه می‌تواند مدیر مستأجرهای دیگر را ایجاد کند. ثبت‌نام عمومی و صورتحساب در این نسخه وجود ندارد.

## ساخت اتصال

از اتصال‌ها، گزینهٔ اتصال جدید را انتخاب کنید. LOCAL برای ذخیره‌ساز نمونهٔ کاملاً آفلاین است. REST، SOAP، GRAPHQL و ODATA برای HTTP هستند. JDBC به درایور سازگار پایگاه داده نیاز دارد. REDIS و MONGODB قابلیت‌های محدود و مشخص‌شده در [راهنمای کانکتورها](connectors.md) را دارند.

نام، تنظیمات JSON و اطلاعات ورود را در محل مخصوص وارد کنید. خالی‌گذاشتن فیلد محرمانه هنگام ویرایش، مقدار قبلی را حفظ می‌کند؛ حذف صریح، مقدار را پاک می‌کند. پاسخ API فقط نام اطلاعات محرمانهٔ تنظیم‌شده را برمی‌گرداند، نه مقدارشان را. گذرواژه را در URL، ثابت پروایدر یا فیلد دلخواه تنظیمات قرار ندهید؛ چنین مقادیری خودکار محرمانه تشخیص داده نمی‌شوند.

مقصدهای خارجی باید توسط بهره‌بردار در `HUB_ALLOWED_ORIGINS` مجاز شوند. آدرس خصوصی علاوه بر آن به `HUB_ALLOW_PRIVATE=true` نیاز دارد. JDBC به `HUB_JDBC_PREFIXES` و درایور نصب‌شده نیاز دارد. رابط کاربری نمی‌تواند این محدودیت‌های بهره‌بردار را بردارد.

بازرسی اتصال، متادیتای JDBC یا مجموعه‌های LOCAL را می‌خواند. برای SOAP می‌توان WSDL مستقل نسخهٔ ۱٫۱ را وارد کرد. بازرسی HTTP به معنای تأیید سلامت اتصال نیست و مشخصات راه دور را خودکار دریافت نمی‌کند.

## تولید CRUD

در LOCAL، از بازرسی و سپس تولید CRUD، نام مجموعه را وارد کنید. در JDBC نام دقیق جدول و در صورت نیاز Schema را وارد کنید. چهار پیش‌نویس READ، CREATE، UPDATE و DELETE تولید می‌شود. تولید JDBC به یک کلید اصلی تک‌ستونی که از متادیتا تأیید شده باشد نیاز دارد. جدول بدون کلید اصلی یا دارای کلید مرکب باید پروایدر اختصاصی و بررسی‌شده داشته باشد.

هر پیش‌نویس را بررسی، آزمایش و سپس منتشر کنید. تولید CRUD مجوزهای تجاری ردیف‌های پایگاه دادهٔ شما را طراحی نمی‌کند. حساب پایگاه داده و شرط‌های محدودکننده همچنان باید اصول حداقل دسترسی را رعایت کنند.

## پارامترها و نگاشت

هر پارامتر نام یکتا، نوع، منبع، وضعیت اجباری‌بودن و مقدار پیش‌فرض یا مرجع اختیاری دارد. انواع مجاز STRING، INTEGER، DECIMAL، BOOLEAN، JSON، DATE و DATETIME هستند. تاریخ با قالب `YYYY-MM-DD` و تاریخ‌زمان همراه Offset مانند `2026-10-10T12:00:00Z` ارسال می‌شود. INTEGER باید در عدد صحیح علامت‌دار ۶۴ بیتی جا شود. برای اعداد حساس به دقت، مقدار را به‌صورت رشته و با نوع عددی مناسب بفرستید؛ مرورگر از عدد JavaScript استفاده می‌کند.

| منبع | محل تأمین | امکان تغییر توسط فراخواننده |
|---|---|---|
| INPUT | ورودی اجرا یا پیش‌فرض | بله |
| CONSTANT | ثابت پروایدر | خیر |
| SYSTEM | tenant، principal، correlationId و now | خیر |
| CONFIG | کلید تنظیمات مستأجر | خیر |
| SECRET | اطلاعات محرمانهٔ اتصال | خیر |

پارامتر اعلام‌نشده رد می‌شود. اگر یک مقدار JSON دقیقاً `${customerId}` باشد، نوع مقدار حفظ می‌شود. جایگزینی درون متن طولانی‌تر، رشته تولید می‌کند. مقدار SOAP با XML escaping وارد می‌شود. SQL از پارامتر متصل‌شدهٔ `:customerId` استفاده می‌کند، نه جایگزینی متنی `${...}`. تشخیص خودکار جای‌گذاری‌ها در ویرایشگر جای بررسی نوع و اجباری‌بودن را نمی‌گیرد.

REST از مسیر، Query، Header و بدنهٔ JSON، متن، فرم و Multipart پشتیبانی می‌کند. خروجی باینری محدود و به‌صورت Base64 همراه متادیتا ارائه می‌شود. SOAP به Envelope، نسخه و Action صریح نیاز دارد. GraphQL سند و متغیر می‌گیرد؛ Mutation باید عملیات نوشتن محسوب شود. OData در این نسخه HTTP و `$top`/`$skip` محدود است، نه پیاده‌سازی کامل استاندارد.

`fieldsRoot` یک JSON Pointer مانند `/data/items` است و پیش از نگاشت خروجی اجرا می‌شود. Pointer هر نگاشت نسبت به شیء انتخاب‌شده یا هر ردیف است. نمونه: `{"name":"customerName","pointer":"/name","type":"STRING"}`. در تبدیل XML، نام محلی عنصر، آرایه برای تکرار، `@` برای صفت و `#text` برای متن به کار می‌رود. یکسان‌بودن نام محلی در Namespaceهای متفاوت می‌تواند ابهام ایجاد کند. متن و فایل خودکار به جدول تبدیل نمی‌شوند.

## آزمایش، انتشار و مصرف

پیش‌نویس را با دادهٔ ساختگی آزمایش کنید. اجرای هم‌زمان یا قرارگرفتن در صف ممکن است. برای تکرار همان درخواست منطقی، کلید Idempotency را حفظ کنید؛ برای عملیات تجاری جدید، کلید جدید بسازید. استفاده از همان کلید با محتوای متفاوت خطای تعارض می‌دهد. پس از انتشار، URL نسخه‌دار و OpenAPI نسخهٔ ۳٫۱٫۱ در دسترس است. همهٔ URLهای تولیدشده POST و دارای احراز هویت هستند، حتی اگر عملیات مقصد خواندنی باشد.

```bash
curl -X POST http://127.0.0.1:8080/api/services/customer-directory/v1 \
  -H "Authorization: Bearer $HUB_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: customer-read-example-001' \
  --data '{"input":{},"page":{"index":0,"size":25}}'
```

برای مصرف‌کننده، کلید کوتاه‌عمر INVOKER با شناسه‌های پروایدر موردنیاز بسازید. کلید مدیر اولیه را در فرانت‌اند قرار ندهید و به مصرف‌کنندگان ندهید. لغو انتشار، اثرهای قبلی در مقصد را برنمی‌گرداند. واردکردن OpenAPI تنها از زیرمجموعهٔ JSON، پیش‌نویس می‌سازد و ارجاع‌های دلخواه راه دور را حل نمی‌کند.

## خطا و بازیابی

فقط عملیاتی که خود کانکتور آن را خواندنِ امن برای تکرار بداند، خودکار تکرار می‌شود. صرف PUT بودن متد یا READ بودن برچسب، ایمنی را ثابت نمی‌کند. نتیجهٔ نامشخص نوشتن، UNKNOWN می‌شود. مقصد را مستقل بررسی کنید و سپس CONFIRMED_SUCCESS یا CONFIRMED_NO_EFFECT را ثبت کنید. هیچ‌کدام نوشتن را خودکار تکرار نمی‌کند. جزئیات صف، نگهداری و تطبیق در [راهنمای عملیات](operations.md) آمده است.
