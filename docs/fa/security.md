# مدل امنیت و مرزهای استقرار

[English](../en/security.md) · [Deutsch](../de/security.md).

این نسخه پیش‌نمایش مهندسی است، نه محصول دارای آزمون نفوذ مستقل یا گواهی امنیت. عبور از آزمون‌های محلی مجوز قراردادن مستقیم برنامه روی اینترنت نیست.

## اعتماد و هویت

بهره‌بردار کلید، تنظیمات شبکه و JARهای نصب‌شده را کنترل می‌کند. مدیر اتصال و کلیدها را می‌سازد. طراح نویسندهٔ مورداعتماد SQL و اتصال است. فراخواننده فقط ورودی اعلام‌شدهٔ پروایدر مجاز را می‌فرستد. مرز مستأجر در سرور بررسی می‌شود. درایور و افزونه اختیار فرایند JVM را دارند و Sandbox ادعا نشده است.

کلید API با تصادف قوی تولید می‌شود، فقط هش آن ذخیره و اصلش یک بار نمایش داده می‌شود. نقش، Scope، انقضا و ابطال کنترل می‌شوند. کلید Bootstrap ویژه، بدون انقضا و از API عادی غیرقابل‌ابطال است. تغییر `HUB_ADMIN_TOKEN` پس از راه‌اندازی، آن را عوض نمی‌کند. بازیابی و گردش کلید مدیریتی و ترجیحاً OIDC/SSO از پیش‌شرط‌های تجاری است. برای عوض‌کردن کلید، کاتالوگ دارای سابقهٔ کسب‌وکار را حذف نکنید.

توکن مرورگر فقط در حافظه است؛ Local Storage فقط زبان را نگه می‌دارد. کوکی احراز هویت و Wildcard CORS وجود ندارد. این موضوع بخشی از ریسک CSRF را کم می‌کند، نه XSS، سرقت توکن یا طراح مخرب را. CSP محدود و خروجی متنی Escape‌شده پیاده شده است. Harness رابط کاربری اثبات اجرای CSP در مرورگر عادی نیست.

## رمزنگاری و اطلاعات

کاتالوگ با AES-256-GCM رمز می‌شود. `master.key` محلی برای توسعه است و در برابر سرقت کل پوشه جداسازی ایجاد نمی‌کند. در استقرار کنترل‌شده از `HUB_MASTER_KEY` مدیریت‌شدهٔ خارجی، دسترسی فایل محدود و Backup جدا از کلید استفاده کنید. حافظهٔ فرایند و Crash Dump می‌توانند متن اصلی داشته باشند. KMS/HSM و گردش Master Key پیاده نشده‌اند.

Audit بدنهٔ درخواست را ذخیره نمی‌کند، اما Job، نتیجهٔ Idempotency و دادهٔ LOCAL می‌توانند اطلاعات تجاری داخل کاتالوگ رمز‌شده داشته باشند. خروجی تنظیمات Backup یا DLP نیست. مقدار محرمانه در SQL Literal، توضیح، Header یا ثابت علامت‌نخورده ممکن است باقی بماند. قبل از اشتراک بررسی کنید. Audit حداکثر پنج‌هزار رکورد در کل مستأجرها دارد و آرشیو تغییرناپذیر خارجی نیست.

## امنیت مقصد

HTTP، Redis و MongoDB به Origin دقیق مجاز نیاز دارند؛ آدرس خصوصی به Opt-in اضافی نیاز دارد. آدرس Link-local و متادیتای ابری، unspecified و Multicast رد می‌شوند. Redirect دنبال نمی‌شود و بررسی پیش‌فرض گواهی/نام میزبان JDK غیرفعال نشده است. JDBC Prefix جدا و فهرست گزینه‌های خطرناک ممنوع دارد.

**ریسک باقی‌مانده:** بررسی DNS و اتصال واقعی به یک IP ثابت Pin نشده‌اند. مقابله با DNS Rebinding و TOCTOU به Egress Firewall واقعی یا Proxy کنترل‌شده نیاز دارد. اعتبارسنجی URL به‌تنهایی کافی نیست. افزونه می‌تواند کنترل شبکهٔ برنامه را دور بزند و باید کد مورداعتماد حساب شود. راهنمای [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) مبنای دفاع چندلایه است.

## SQL، XML و منابع

PreparedStatement و CallableStatement مقدار را Bind می‌کنند. شناسهٔ CRUD با متادیتا کنترل می‌شود. SQL دلخواه هنوز هرکاری را که حساب پایگاه اجازه دهد انجام می‌دهد. حداقل مجوز، حساب جدا و بررسی انتشار لازم است. تراکنش سراسری میان Hub و مقصد ادعا نشده است.

XML، DTD، Entity خارجی، XInclude و دریافت Schema خارجی را ممنوع می‌کند. Importهای WSDL حل نمی‌شوند. عمق، اندازه، صفحه و هم‌زمانی محدود است. راهنمای [OWASP XXE](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html) هنگام تغییر Parser باید رعایت شود. ابهام نام محلی Namespace محدودیت نگاشت است.

## قبل از دسترسی بیرونی

HTTPS را در Reverse Proxy کنترل‌شده خاتمه دهید، JVM را به Loopback یا شبکهٔ محافظت‌شده محدود کنید، Egress را ببندید، نسخهٔ درایورها را بررسی و Restore واقعی را آزمایش کنید. جداسازی را روی Schema واقعی ثابت کنید. آزمون نفوذ، بار و مرورگر بومی مستقل هنوز لازم است. Demo را در محیط مشتری فعال نکنید. Pruning حفاظت کلیدهای قدیمی در برابر تکرار را پایان می‌دهد. سیاست حریم خصوصی و نگهداری به بررسی سازمانی واجدصلاحیت نیاز دارد؛ گواهی GDPR یا انطباق مشابه ادعا نشده است.
